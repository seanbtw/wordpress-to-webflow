# Scripts

Capture, redirect and verification scripts for a WordPress to Webflow migration. Every script but `archive-check.py` (which takes its two paths on the command line) reads its site values from one config file, found in this order: `--config <path>`, the `SITE_CONFIG` environment variable, `./site.config.json` in the current folder. Paths in the config are relative to the folder the config file is in (your project folder). Start from `../assets/site.config.example.json`.

Two folders hold everything: `paths.inventoryDir` (facts collected from WordPress, written as `<inventoryDir>` below) and `paths.verifyDir` (what the checks write, `<verifyDir>` below; the one file written elsewhere is `<inventoryDir>/redirects.csv`, by `build-redirects.py`). Each script's header comment lists its exact inputs, outputs and exit codes. A script stops with a message naming the config key when one it needs is not set.

| `site.mjs`, `site_config.py` | Never on their own: the config loaders the other scripts import | The config file | Nothing |
| `wf-api.mjs` | Never on its own: the Webflow API helper | `WEBFLOW_TOKEN` in the environment | Nothing |

| `archive-check.py` | Phase 0, straight after unpacking the backup | The zip and the extracted folder on the command line (no config) | A summary on standard output, optionally `--report <file>` and both copies of every case-only name pair in `--extract-collisions <folder>` |
| `cms-counts.mjs` | Phase 2, after the import, and after anything that may touch the CMS (a backup restore) | `WEBFLOW_TOKEN`, `webflow.collections`, `<inventoryDir>/cms-expected.json` | `<verifyDir>/cms-counts-<time>.json` |
| `measure-blocks.mjs` | Phase 1 and Phase 3 for each block, Phase 4 and Phase 7 for whole templates and pages | Local WordPress, staging, a spec file naming each block's path and selector on both sides, optional `checks.measure.*`; Playwright | `<verifyDir>/measure/<name>.json` |
| `heading-sequence.mjs` | Phase 4 as soon as templates exist, after every template change, and Phase 7 | Local WordPress, staging, `staging-paths.json`, optional `urls.csv` and `checks.headings.*`; Playwright | `<verifyDir>/heading-sequence.json`, `heading-sequence.md` |
| `compare-bodies.mjs` | Phase 4 once the templates are published, and Phase 7: rich-text bodies as rendered, against the local WordPress copy (the Phase 2 check is the converter's own comparison of its output) | Local WordPress, staging, `checks.bodies.*`, optional `urls.csv`; Playwright, cheerio | `<verifyDir>/bodies/rendered-compare-<type>.json` and screenshots |
| `glued-words.mjs` | Straight after the first page insert, then Phase 4 and Phase 7. `--rendered` compares the text a browser shows (use it for the run over every page); `--all` takes every staging path | Local WordPress, staging; paths on the command line or `staging-paths.json`; optional `urls.csv`, `checks.glued.*`; Playwright for `--rendered` | JSON on standard output, the count of pages compared on standard error |

| `colour-check.mjs` | Phase 4 once the templates are published, and Phase 7. `--all` checks every staging path at 390 and 1440: each inline colour on WordPress against the same text on staging, and every text on staging against what is behind it. | `console-check.mjs` | Phase 5 and Phase 7; `--compare` before and after a change to a live site | Staging, `<verifyDir>/staging-paths.json` or `checks.console.paths`; Playwright | `<verifyDir>/console-check.json` or `console-compare.json` |

## Install

- **Node 20.18.1 or newer** (the scripts use built-in `fetch` and top-level `await`).
- **Python 3.9 or newer**, standard library only. Run the Python scripts with `python3 -I`.
- **curl** on the PATH (used by the JSON-LD checks and the two Python scripts that fetch).
- In this folder: `npm install`, then `npx playwright install chromium`. Four packages are needed, pinned in `package.json`: `playwright` (the browser checks: `crawl-links`, `console-check`, `compare-bodies`, `bundle-swap`, `measure-blocks`, `heading-sequence`, `page-sweep`, `colour-check`, and `glued-words --rendered`), `cheerio` (`compare-bodies`), and `pixelmatch` with `pngjs` (`page-sweep`, to locate where two parts differ). The other scripts need no install.

## Notes

- **The Webflow token** is read only from the `WEBFLOW_TOKEN` environment variable. It is never read from a file, printed or written. Export it in the shell for the run; do not add it to `site.config.json`.
- **Python and TLS on some Macs**: Python's `urllib` can fail with `CERTIFICATE_VERIFY_FAILED` because that Python has no certificate store. The Python scripts fetch through `curl` instead.
- **What touches the network**: each script's header says which hosts it calls. Beyond the hosts in your config or on the command line, that is: the Webflow API (`staging-paths`, `sitemap-exclude`, `cms-counts`), whatever a page loads when a browser check opens it, the host Webflow serves a share picture from (`seo-check.mjs`), and, for `live-capture.mjs`, the destination of any old redirect that leaves the site (each redirect is followed to its end).
- **Only `sitemap-exclude.mjs` changes anything** outside your project folder (the sitemap setting of the items you name). Every other script reads.
- **Importing redirects in Webflow replaces every existing redirect.** `redirects-import.csv` is always the full list.
- **Copying these scripts into a project**: they read every site value from the config and write only under `<verifyDir>` and `<inventoryDir>`. Keep any script you add the same way. A copied script with the last project's folder typed into it writes there without complaint, and one with the last site's Webflow id typed into it writes to that site, so grep for the previous project's path, domain, local port and Webflow ids before the first run.
- **A check that compared nothing is not a pass.** `seo-check.mjs` says "NOT COMPARED" when `seo.csv` has no `og_image` column, and `glued-words.mjs` and `page-sweep.mjs` print how many pages they compared. Read those lines.
- **`staging-paths.json` is the base of most checks.** Run `staging-paths.mjs` again after adding pages or publishing new items, or the checks will miss them.
